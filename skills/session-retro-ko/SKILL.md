세션을 닫기 전에 회고 1패스를 돈다. 순서는 고정이다 — **판정 → 4축×2렌즈 → 🟢 판정 → 원장 기록·카드 → 최종 메시지(빼기·더하기 두 표) → 사람 GATE → 실행 → (선택) 코퍼스 노드.**

출력 형식은 [RETRO-FORMAT.md](./RETRO-FORMAT.md), 실물 예시는 [examples/worked-example.md](./examples/worked-example.md).

**사람 GATE 없이 아무것도 발행하거나 옮기지 않는다.** 자기채점 무인승인은 false rec 를 상시 적재되는 rule 로 굳힌다.

**판단 근거가 되는 비율·확률은 [`ledger.py`](./ledger.py) 출력만 쓴다. 말로 매기지 않는다.** 표가 읽기를 대신하는 구조라 보정 안 된 숫자는 곧 거수기다 (설계 검토 실측: 말로 매긴 카드 확률 5종 중 4종이 발동 조건이 정하는 상수였다). 크기(chars) 같은 측정값은 Python 으로 잰다.

## 이 스킬이 도는 시점

세션이 끝나기 전, 대화가 아직 살아 있을 때다. 발행·이동 사실이 세션 대화에 남아야 한다. 동봉된 `session-seal` 스킬을 쓴다면 봉인 **전**에 돈다 — 그래야 sealed 스냅샷이 근거를 품는다. **코퍼스 노드만은 봉인 후**다 — 노드의 출처는 sealed 세션이어야 한다.

## rule 이 사는 곳 — 위치가 곧 상태

이 스킬은 **rule 하나 = 파일 하나**를 전제로 한다. 상시 가드레일은 `~/.claude/rules/*.md` 에 발행하고, Claude Code 는 이 디렉터리를 전 프로젝트 공통 지침으로 읽어 간다. rule 의 상태는 파일이 어느 폴더에 있느냐로 정해진다:

| 폴더 | 상태 | 컨텍스트 |
|---|---|---|
| `~/.claude/rules/` | 실림 | 매 세션 실린다 |
| `~/.claude/rules-probation/` | 격리 | 안 실린다 — rule 없이 그 행동이 유지되는지 관측한다 |
| `~/.claude/rules-archive/` | 보관 | 안 실린다 |

격리 폴더는 반드시 `rules/` 의 **바깥 형제**여야 한다. `rules/` 는 하위 폴더까지 재귀로 읽히므로 안쪽에 두면 격리가 무효다.

## 원장과 `ledger.py`

- 원장: `~/.claude/session-retro-ko/verdicts.csv` (`SESSION_RETRO_DIR` 로 폴더를 바꾼다). **`ledger.py` 만 쓴다** — 손으로 편집하지 않는다. 없으면 첫 `add` 가 만든다. 판정값이 한국어로 저장되므로 영어판 `session-retro` 와 원장을 공유하지 않는다.
- 판(rev) = rule 파일 내용 해시. rule 을 고치면 그 rule 의 관측 창이 새로 시작한다.
- 확률: 기준 실패율 p = 실린 rule 들의 세션 단위 실패 비율. 격리 행의 P 는 "평균 rule 이 이만큼 연속 작동할 확률", 고치거나빼기 행의 P 는 "평균 rule 이 이만큼 이상 실패할 확률" — 작을수록 그 rule 이 평균과 다르다는 뜻이다. **원장이 비어 있는 동안은 기준이 없어 확률 제안이 나오지 않는다** — 판정이 쌓이면서 카드가 생긴다.
- 종료 코드: `0` 통과 · `3` 위반(입력을 고쳐 다시 실행) · **그 외 = 도구 실패 → 원장을 건드리지 말고 사용자에게 보고.**
- 임계값은 `ledger.py` 상단 상수 블록이 단일 권위다. 이 문서는 숫자를 복제하지 않는다.
- 실행: `python <skill-dir>/ledger.py <명령> …` (Python 3.8+). `<skill-dir>` 는 이 SKILL.md 가 있는 디렉터리 — 모르면 Glob 으로 `**/session-retro-ko/ledger.py` 를 찾는다. `add`·`cards`·`gate` 는 `--date <YYYY-MM-DD> --project <cwd 최하위 이름> --slug <가제>` 를 함께 받는다 (`stats`·`leaks` 는 rule 이름만). 테스트는 같은 폴더 `tests/`.

| 명령 | 언제 |
|---|---|
| `add --slug S --file rows.json` | 4단계 — 판정을 원장에 (하나라도 위반이면 0행). **회고마다 새 slug** — 이미 있는 세션 키면 exit 3. 같은 회고의 추가분만 `--append` |
| `cards --slug S` | 4단계 — 빼기 표와 참고줄 |
| `stats <rule>` | 4단계 — 더하기 보강 행의 근거 |
| `leaks <rule>` | 7단계 — 격리 accept 직전 |
| `gate --slug S --rule R --proposal P --decision D --note N` | 4·7단계 — 빼기 결정마다 (reject 도). P 는 카드의 제안 열 값 그대로. accept 면 파일을 옮긴다 |

선택 환경변수 — 없으면 그 기능만 빠진다. 재기록률과 `leaks` 는 "미설정" 이라고 말해 빈 결과와 구분되고, `sealed N` 은 근거 열에서 생략된다:

| 변수 | 켜지는 것 |
|---|---|
| `SESSION_SEAL_DIR` | 카드 근거의 `sealed N` — 창 기간의 봉인 세션 수. 회고 수와 나란히 보여 회고가 빠진 세션을 드러낸다. 동봉 `session-seal` 과 같은 변수다 |
| `SESSION_RETRO_CORPUS` | 더하기 참고줄의 재기록률 — 8단계 코퍼스 노드 파일이 있는 폴더 |
| `SESSION_RETRO_PROJECTS` | `leaks` 가 `<그 폴더>/*/CLAUDE.md` 까지 본다 |

## 1단계 — 판정

이번 세션에 관련된 `rules/` rule, 그리고 **`rules-probation/` 의 rule 전부**를 판정한다. 격리 rule 은 컨텍스트에 없으니 파일을 읽고 판정한다 — 그 행동이 필요했던 상황이 이번 세션에 없었으면 `무관`. 3단계 grep 에서 이번 세션에 필요했던 **보관 rule** 이 나오면 그 rule 도 판정한다 (보관 rule 이 돌아오는 유일한 길이다).

- verdict 는 `작동` · `부분작동` · `미작동` · `무관` 넷 중 하나의 **맨 글자**. 꾸밈·단서·"단 우연" 같은 주석은 note 로.
- note 는 구체 사건 — 이 note 가 빼기 표 아래 "실패 사건" 으로 사용자 앞에 나간다. rule 이름만 쓰지 않는다. 격리 rule 이면 "필요했던 상황 → 실제로 한 행동".
- **미작동을 숨기지 않는다.** rule 이 있었는데도 밟았으면 그렇게 적는다 — 고치거나빼기의 유일한 입력이다.
- 실린 rule 이 이번 세션과 무관하면 행을 쓰지 않는다 (`무관` 은 격리 rule 전용). memory 는 판정하지 않는다.
- **격리가 새는지 본다**: 세션 첫머리 컨텍스트에 `rules-probation` 경로의 rule 내용이 보이면 격리가 무효다 — 판정하지 말고 사용자에게 보고한다.
- 작업 텍스트로 출력한다. 항목당 한 줄.

## 2단계 — 4축 × 2렌즈

축은 **잘한 것 / 실수한 것 / 어려웠던 것 / 배운 것**, 렌즈는 **엔지니어링 / 비즈니스**. 작업 텍스트로 — 봉인 스냅샷과 코퍼스 노드의 재료다.

- 모든 항목은 **이 세션의 구체 사건에 앵커**한다. 수치·출력·에러 문구를 인용할 수 있으면 인용한다. 추상 훈계는 항목이 아니다.
- **실수 축을 비워 두지 않는다.** 에이전트 본인의 실수를 먼저 적는다.
- 비즈니스 렌즈는 "돈"이 아니라 사용자·진도·산출물 형태·협업 마찰 (학습 프로젝트면 학습 효율).
- 어려웠던 것 ≠ 실수 — 비용이 컸던 지점이고, 다음에 도구를 바꿀 후보다.
- 배운 것은 "X 일 때는 Y 한다" 형태로. 여기 없는 것이 🟢 로 튀어나오면 앞 단계가 부실한 것이다.

## 3단계 — 🟢 판정

판단은 **이진**: `🟢 후보 (타입)` 또는 `미분류(사유 한 줄)`. 강도 등급을 두지 않는다 — 낮게 매긴 항목이 영구 매장된다. `미분류` 는 "가치 없음" 이 아니라 "아직 triage 안 됨" 이다.

- **중복 검사**: 실린 rule 은 컨텍스트에 있어 공짜다. 거기에 더해 `rules-probation/`·`rules-archive/` 를 **grep** 한다 — 컨텍스트에 없는 rule 이 재발행되는 뒷문을 막는다.
- **대상이 격리·보관 rule 이면 보강하지 않는다** — 1단계 판정 행을 쓰면 빼기 표에 복귀 제안이 뜬다 (그 rule 없이 실패한 것이 곧 격리 실험의 결과다).
- 빈도(sources 개수)를 중요도로 쓰지 않는다 — 일회성 통찰이 반복된 짜증보다 클 수 있다. 타 프로젝트 memory·노트와의 중복은 부분뷰라 발행 시점에 확인한다.

| 노드가 ~이면 | 산출물 | 포맷 권위 |
|---|---|---|
| 상시 행동 가드레일 | **rule** (`~/.claude/rules/*.md`) | [RULE-FORMAT.md](./RULE-FORMAT.md) |
| 입력·출력 있는 반복 절차 | **skill** | 쓰고 있는 skill 작성 도구 (예: `skill-creator`) |
| 비가역·의외·trade-off 결정 | **ADR** (repo) | 프로젝트 ADR 포맷, 없으면 아래 미니 스펙 |
| 재사용 사실 / 사용자 피드백 | **memory** | 동봉된 `dream` 스킬 |
| 멀티에이전트 오케스트레이션 | **workflow** | 그런 기능이 있는 환경일 때만 |
| 이미 기존 rule 이 강제 | **없음** — 관측만, 미분류 | — |

**ADR 미니 스펙** — 프로젝트에 자체 포맷이 없을 때: 첫 문장 = 결정 + 왜 + 감수하는 비용 (거부 결정이면 명시적으로 NO). 기본은 한 문단. 역전 비용이 큼 ∧ 맥락 없이 의외 ∧ 실제 trade-off — 셋 다 참일 때만 쓴다.

## 4단계 — 원장 기록과 카드

1. 1·3단계 판정을 `rows.json` 으로 (임시 폴더) — `[{"rule": "verify-your-evidence", "verdict": "부분작동", "note": "…"}, …]`.
2. `ledger.py add` → `ledger.py cards`. exit 3 이면 stderr 대로 입력을 고쳐 다시. 격리 rule 판정이 빠지면 cards 가 3 으로 멈춘다.
3. **`관련드묾` 행은 그 rule 의 `적용 범위` 를 읽고 좁을 때만 남긴다.** 이 행이 재는 것은 "상황이 드물었나" 가 아니라 "회고가 그 rule 을 주목했나" 다 — 범위가 넓은데 주목받지 못한 rule 이 걸린다 (실측: 거의 모든 구현 세션에 해당하는 보고 방식 rule 이 31회고 중 4회만 채점돼 걸렸다). 뺀 행은 작업 텍스트에 사유 한 줄 + `gate --proposal 관련드묾 --decision reject --note "회고 필터: 적용 범위 넓음"` — 매 회고 다시 뜨지 않게 한다.
4. 더하기 표의 보강 행마다 `ledger.py stats <rule>` 를 근거로 붙인다.

## 5단계 — 최종 메시지

**빼기 표 → 더하기 표 → GATE 안내**, 이것만. 빼기가 먼저다 — rule 을 늘리기 전에 줄일 것을 먼저 보게 하는 제동이다. 형식은 [RETRO-FORMAT.md](./RETRO-FORMAT.md).

## 6단계 — 사람 GATE

- 번호별로 답을 받는다. `고치거나빼기` 는 **고치기 / 격리 / 반려**, 나머지 빼기는 **accept / reject**, 더하기는 **accept / reject / edit**. **반려와 문구 수정도 정당한 결과**라고 적는다.
- 선택지 버튼으로 처리하지 않는다 — 표를 읽고 번호로 답하게 한다.
- 더하기 행에는 **과거 반려 이력**을 단서로 (프로젝트 memory 의 발행 기록, 코퍼스를 쓰면 그 반려 표기도). 거절당한 제안이 이름만 바꿔 들어오지 않게. 빼기 행의 반려 이력은 스크립트가 `n회 반려` 로 붙인다.

## 7단계 — 실행

accept 된 것만 한다.

- **빼기**: 결정마다 `ledger.py gate` — **reject 도 기록한다** (같은 제안이 매 회고 반복되지 않는다).
  - 격리·관련드묾 accept 전에 `ledger.py leaks <rule>`. 내용을 싣는 자리(hook · CLAUDE.md · MEMORY.md)는 남길지 사용자에게 묻는다. 이 스킬의 파일이 그 rule 을 이름으로 가리키면 고친다 — `examples/` 의 실출력 기록은 과거 사실이라 고치지 않는다. 격리하면 그 rule 은 다음 세션부터 컨텍스트에서 빠진다 — 상시 비용 절감은 이 시점에 온다.
  - 고치거나빼기: **고치기** = `gate --proposal 고치거나빼기 --decision accept` 후 RULE-FORMAT 보강 규율로 재작성 (판이 바뀌어 창이 새로 시작한다) · **격리** = `gate --proposal 격리 --decision accept` · **반려** = `gate --proposal 고치거나빼기 --decision reject`.
- **더하기**: 해당 포맷 권위를 **읽고** 발행한다. rule 은 매 세션 실리므로 길이가 곧 상시 비용 — RULE-FORMAT 의 분량 규율을 지킨다.
- 끝으로 프로젝트 memory 에 **발행·반려·미분류를 각 한 줄** — 다음 회고의 반려 이력 단서가 된다.

## 8단계 (선택) — 코퍼스 노드

세션을 가로지르는 회고 저장소를 따로 운영할 때만 의미가 있다. 안 쓰면 7단계에서 끝낸다.

노드는 5범주 파일로 나눈다 — 이 이름들은 [RETRO-FORMAT.md](./RETRO-FORMAT.md) 작업 텍스트의 범주이기도 하다. 코퍼스를 안 써도 이름은 유지한다 — *어떤 종류*의 것인지 말하게 만드는 장치다.

| 파일 | 담는 것 |
|---|---|
| `a-mistakes.md` | 달리 갈 수 있었는데 잘못된 것 |
| `b-insights.md` | 앞으로의 행동을 바꾸는 배움 |
| `c-improvements.md` | 프로세스·도구를 바꿀 만한 개선 |
| `d-deferred.md` | 미뤄둔 합의 + 다시 꺼낼 조건 |
| `e-recurring.md` | 여러 세션에 걸쳐 반복된 양상 |

`ledger.py` 가 읽는 노드 모양은 이것뿐이다 — `### {노드 제목}` 줄, 그 바로 아래 11줄 안에 `sources: [[YYYY-MM-DD - 세션 제목]], …` (가장 이른 날짜가 노드가 태어난 세션). 같은 노드가 다른 세션에서 다시 관측되면 sources 에 링크를 더한다. 그 폴더를 `SESSION_RETRO_CORPUS` 로 알려 주면 더하기 참고줄이 "1회 관측 노드가 이후 회고에서 다시 기록된 비율" 을 센다.

발행된 산출물은 노드에서 `✅ 발행 (rule:<파일>, 날짜)` 로 역링크한다. 격리·보관은 노드를 고치지 않는다 — 현재 상태의 권위는 원장과 파일 위치, `✅ 발행` 은 발행 이력이다.

## 금기

- ❌ 사람 GATE 없이 발행·이동
- ❌ 판단 근거 비율·확률을 말로 매기기 — `ledger.py` 출력만
- ❌ 원장 CSV 를 손으로 편집, 또는 exit 3 이 아닌 실패에 원장을 고치기
- ❌ 격리 rule 판정 빠뜨리기, 다른 회고의 slug 재사용
- ❌ 봉인 안 된 세션을 코퍼스 `sources:` 에 1급으로
- ❌ 재현 가능한 근거 없는 추상 훈계를 항목으로
- ❌ 실수 축을 비워 두기
- ❌ 강도 등급(🟡⚪) — 이진 판정을 지킨다
- ❌ 단일 권위(프로젝트 ADR 포맷 · `ledger.py` 임계값)를 이 스킬 문서에 복제
