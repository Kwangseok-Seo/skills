<what-to-do>

세션을 닫기 전에 회고 1패스를 돈다. 순서는 고정이다 — **재사용 성적 → 4축×2렌즈 → 🟢 판정 → 사람 GATE → 발행 → (선택) 코퍼스 노드.**

출력 형식은 [RETRO-FORMAT.md](./RETRO-FORMAT.md) 를 따른다. 실물 예시는 [examples/worked-example.md](./examples/worked-example.md).

**사람 GATE 없이 아무것도 발행하지 않는다.** 이 한 줄이 이 스킬의 존재 이유다 — 자기채점 무인승인은 false rec 를 상시 적재되는 rule 로 굳힌다.

</what-to-do>

## 이 스킬이 도는 시점

세션이 끝나기 전, 대화가 아직 살아 있을 때다. 회고에서 나온 산출물(rule·ADR)은 세션 **안에서** 발행되고, 그 발행 사실이 세션 대화에 남아야 한다.

동봉된 `session-seal` 스킬을 쓴다면 봉인 **전**에 돈다 — 그래야 sealed 스냅샷이 발행물의 근거를 품는다.

## rule 이 저장되는 곳

이 스킬은 상시 가드레일을 `~/.claude/rules/*.md` 에 markdown 파일로 발행한다. Claude Code 가 이 디렉터리를 전 프로젝트 공통 지침으로 읽어 간다.

그 디렉터리를 자동으로 읽지 않는 환경이라면 `~/.claude/CLAUDE.md` 에 덧붙이거나, 이미 쓰고 있는 상시 적재 위치를 그대로 쓴다. 목적지만 바뀔 뿐 아래 내용은 그대로다.

## 1단계 — 재사용 성적을 먼저 보인다

**회고의 첫 섹션은 이번 세션의 잘잘못이 아니라 직전에 발행한 rule 이 실제로 쓰였는가다.** 발행이 목적이 아니라 재사용이 목적이기 때문이고, 성적표를 앞에 두면 "또 rule 하나 늘리기"에 제동이 걸린다.

전역 rule 은 이미 컨텍스트에 있으므로 훑는 데 비용이 안 든다. 이번 세션에 적용됐을 rule 을 고르고 각각에 대해:

- **어디서 어떻게 재사용됐는지** 구체 사건으로 (rule 이름만 나열하지 않는다)
- **작동/부분작동/미작동** 판정. rule 이 있었는데도 밟았으면 그렇게 적는다 — 그게 rule 수정 신호다
- 이번 세션과 무관한 rule 은 아예 안 올린다

**아직 발행한 게 없다면(첫 실행)** 한 줄로 그렇게 적고 2단계로 간다. 표를 지어내지 않는다.

미작동이 반복되면 그 rule 은 **문구가 약하거나 자리가 틀린 것**이다. 새 rule 을 얹기 전에 기존 것을 고치는 쪽을 먼저 검토한다.

## 2단계 — 4축 × 2렌즈

축은 **잘한 것 / 실수한 것 / 어려웠던 것 / 배운 것**, 렌즈는 **엔지니어링 / 비즈니스**.

- 모든 항목은 **이 세션의 구체 사건에 앵커**한다. "더 신중해야 한다" 같은 추상 훈계는 항목이 아니다 — 무엇을 관찰했고 무엇이 달라졌는지 적을 수 없으면 올리지 않는다.
- **실수 축을 비워 두지 않는다.** 실수가 없는 세션은 회고가 얕은 것이다. 자기 실수(에이전트 본인의 실수)를 먼저 적는다.
- 비즈니스 렌즈는 "돈"이 아니라 **사용자·진도·산출물 형태·협업 마찰**이다. 학습 프로젝트라면 학습 효율이 여기 온다.
- 어려웠던 것은 실수와 구분한다 — 어려웠던 것은 잘못이 아니라 **비용이 컸던 지점**이고, 다음에 도구를 바꿀 후보다.

## 3단계 — 🟢 판정

판단은 **이진**이다: `🟢 후보 (타입: rule|skill|guardrail)` 또는 `미분류`. 강도 등급(🟡⚪)을 두지 않는다 — 낮게 매긴 항목이 영구 매장되고 "검토 완료" 착각을 만든다.

- **`미분류` 는 "가치 없음"이 아니라 "아직 triage 안 됨"** 이다. 사유를 한 줄 적는다(예: *기존 rule 이 이미 커버*, *컴파일러가 항상 잡아 가드레일 가치 낮음*).
- **중복 검사는 전역 rule 한정으로 반드시 한다.** 전역 rule 은 컨텍스트에 있어 공짜·정확하다. 타 프로젝트 memory/노트와의 중복은 부분뷰라 거짓음성 위험이 있으니 판정에 박지 말고 발행 시점에 확인한다.
- 빈도를 중요도로 쓰지 않는다. 일회성 통찰이 반복된 짜증보다 클 수 있다.

산출물 결정은 ROUTE 표를 따른다:

| 노드가 ~이면 | 산출물 | 포맷 권위 |
|---|---|---|
| 상시 행동 가드레일 | **rule** (`~/.claude/rules/*.md`) | [RULE-FORMAT.md](./RULE-FORMAT.md) |
| 입력·출력 있는 반복 절차 | **skill** | 쓰고 있는 skill 작성 도구 (예: `skill-creator`) |
| 비가역·의외·trade-off 결정 | **ADR** (repo) | 프로젝트 ADR 포맷, 없으면 아래 미니 스펙 |
| 재사용 사실 / 사용자 피드백 | **memory** | 동봉된 `dream` 스킬 |
| 멀티에이전트 오케스트레이션 | **workflow** | 그런 기능이 있는 환경일 때만 |
| 이미 기존 rule 이 강제 | **없음** — 관측만, 미분류 | — |

**ADR 미니 스펙** — 프로젝트에 자체 포맷이 없을 때 이 정도면 쓸 수 있다:

- 첫 문장 = 결정 + 왜 + 감수하는 비용. 거부 결정이면 명시적으로 NO 라고 쓴다.
- 기본은 한 문단. 섹션은 값어치를 할 때만 추가한다.
- 셋 다 참일 때만 쓴다: 역전 비용이 큼 ∧ 맥락 없이 의외 ∧ 실제 trade-off 가 있었음. 자명·국소·가역 결정은 ADR 이 아니다.

## 4단계 — 사람 GATE

🟢 후보를 **산문으로** 제시하고 accept/reject/edit 를 묻는다.

- **선택지 클릭으로 처리하지 않는다.** 읽기가 강제돼야 거수기가 안 된다. 후보마다 "무엇을 관찰했고 왜 rule 감인가"가 한눈에 보이게 쓴다.
- 반려·문구 수정도 정당한 결과라고 명시한다.
- 과거에 사용자가 **거절한 영역**이 있으면 그 사실을 후보 옆에 밝힌다. 거절당한 제안이 이름만 바꿔 뒷문으로 들어가지 않게.

## 5단계 — 발행

accept 된 것만 만든다. 각 산출물은 해당 포맷 권위를 **읽고** 따른다.

- rule 은 **매 세션 컨텍스트에 실린다**. 길이가 곧 상시 비용이다 — [RULE-FORMAT.md](./RULE-FORMAT.md) 의 분량 규율을 지킨다.
- 발행 후 프로젝트 memory 에 결과를 한 줄 남긴다(무엇을 발행했고 무엇을 왜 미분류했는지). 다음 세션 1단계의 재료가 된다.

## 6단계 (선택) — 코퍼스 노드 기록

세션을 가로지르는 회고 저장소를 따로 운영할 때만 의미가 있다. 안 쓰면 5단계에서 끝낸다.

노드는 5범주로 분류한다:

| 범주 | 담는 것 |
|---|---|
| `a-mistakes` | 달리 갈 수 있었는데 잘못된 것 |
| `b-insights` | 앞으로의 행동을 바꾸는 배움 |
| `c-improvements` | 프로세스·도구를 바꿀 만한 개선 |
| `d-deferred` | 미뤄둔 합의 + 다시 꺼낼 조건 |
| `e-recurring` | 여러 세션에 걸쳐 반복된 양상 |

이 이름들은 [RETRO-FORMAT.md](./RETRO-FORMAT.md) 판정표의 범주 열이기도 하다. 코퍼스를 안 써도 이름은 유지한다 — *어떤 종류*의 것인지 말하게 만드는 장치다.

발행된 산출물은 노드에서 `✅ 발행 (rule:<파일>, 날짜)` 로 역링크한다. 세션 봉인도 함께 쓴다면 노드는 **봉인 후**에 쓴다 — 노드의 출처가 아직 진행 중인 세션이 아니라 sealed 스냅샷을 가리키게.

## 금기

- ❌ 사람 GATE 없이 rule/skill 발행
- ❌ 재현 가능한 근거 없는 추상 훈계를 항목으로 올리기
- ❌ 실수 축을 비워 두기
- ❌ 강도 등급(🟡⚪) 도입 — 이진 판정을 지킨다
- ❌ 기존 단일 권위(프로젝트 ADR 포맷·코퍼스 노드 스키마)를 이 스킬 안에 복제
