# 예시 — v2 를 설계한 세션의 회고 1패스

실제로 돈 회고를 발췌·축약한 것. 세션은 이 스킬 자체를 원장 기반으로 다시 설계한 작업이었다 — 적대 검토 네 라운드(R1·R2a·R2b·R3), `ledger.py` 테스트 60개, 변이 53종. 원장에는 과거 회고 31회분 판정이 미리 들어 있었다 (공개판에는 그 이관 명령이 없다 — 빈 원장에서 시작하면 기준 줄이 "표본 없음" 이고 확률 제안이 나오지 않는다).

**이 예시가 보여주는 것**: 작업 텍스트는 재료이고 사용자 앞에는 두 표만 나간다 · `cards` 출력을 고치지 않고 옮기기 · 보강 행에 `stats` 근거 붙이기 · 단서에 인접 반려 이력 밝히기 · 반려도 정당한 결과.

> rule 이름들은 이 사용자가 앞선 회고에서 발행한 것이다. 각자 다를 수밖에 없다 — 베낄 것은 이름이 아니라 형태다.

## 작업 텍스트 (발췌)

**판정**
- `verify-your-evidence` 부분작동: 레드팀 주장 재현·변이 53종은 작동. 그러나 첫 답변에서 독립 표본 ~8개짜리 결과를 "연속 작동은 예측하지 못한다" 로 단정 — R1 이 뒤집음
- `evidence-before-decision` 작동: "작동하면 삭제" 제안에 답하기 전 과거 판정 213건에 대입해 17개 중 12개 반례를 먼저 제시
- `check-your-guardrails` 부분작동: v2 스펙에서 위반과 크래시를 같은 exit 1 로 둠 — R1·R2b 가 잡고 v3 에서 exit 3 으로 분리
- `derive-dont-duplicate` 부분작동: rule 상태를 이벤트 로그와 파일 위치 두 곳에 둠 (R2b blocker) — v3 에서 실물 도출로 해소
- `report-guideline` 부분작동: 실행 예시는 붙였으나 "1-4번 표를 답해 달라" 를 답별 효과 없이 적어 사용자가 "무슨 말이죠?" 로 되물음
- (그 밖에 작동 5건 — `silent-failure-first` · `delegation-policy` · `spec-before-first-build` 등)

**4축**
- 실수(엔지니어링): 표본보다 강한 결론을 먼저 말함 · 이중 상태 설계 · 위반과 크래시가 같은 exit 1 · 편집이 조용히 적용되지 않은 적 2회
- 실수(비즈니스): 결정 요청에 각 답이 하는 일을 붙이지 않아 왕복 1회
- 잘한 것: 사용자 제안을 실데이터로 반증 · 첫 전부 통과(24/24)를 의심해 빈틈 5곳 발견 · 상시 컨텍스트 14%(5,834자) 감축
- 어려웠던 것: 라운드마다 앞 라운드 수정이 새 구멍을 만듦 · 관측 커버리지 23%
- 배운 것: 표에 붙이는 숫자는 같은 종류의 행끼리 값이 달라지는지 먼저 본다 · 결정을 요청할 때는 답별 효과를 같이 적는다

**🟢**
- 1 "발동 조건이 값을 정하는 숫자는 근거가 아니다" b-insights → rule 보강
- 2 "GATE 안내에 답별 효과를 적는다" c-improvements → skill 보강

- 4 세션 중간 격리 구멍 a-mistakes → 미분류(코드로 해소, 테스트 추가)

## 결과

사용자 답: **"1번은 격리 2,3 reject"** — 고치거나빼기 제안에 셋째 선택지인 격리를 골랐다.

1. `ledger.py leaks report-guideline` — 프로젝트 `CLAUDE.md` 두 곳에 그 rule 의 요지가 실려 있었다. 그대로 두고 그 사실을 gate note 에 적었다.
2. `ledger.py gate --proposal 격리 --decision accept --note "사용자 GATE: 고치거나빼기(실패 4/5, P=0.049)에 격리 선택…"` — 파일이 `rules-probation/` 으로 옮겨졌고, 다음 세션부터 컨텍스트에서 빠진다. 이후 회고는 이 rule 을 매번 판정해야 한다 (필요한 상황이 없었으면 `무관`).
3. 더하기 2·3 반려 — 원장이 아니라 프로젝트 memory 에 한 줄씩. 다음 회고가 같은 제안을 다시 올리면 단서에 이 반려가 뜬다.

> 실제 실행에서는 GATE 안내 아래 "각 답이 하는 일" 표를 덧붙였다. 그 표를 포맷에 넣자는 3번 제안이 반려됐으므로, 위 최종 메시지는 포맷의 안내 문장으로 적었다.
