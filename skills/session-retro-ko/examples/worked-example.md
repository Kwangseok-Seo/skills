# 예시 — 마일스톤 둘을 닫은 세션 회고

실제로 돈 회고 1패스를 비식별화한 것. 프로젝트는 언어를 배우면서 동시에 만들던 작은 CLI 도구고, 한 세션에서 마일스톤 둘(인증·설정 / 매니페스트 검증)을 닫았다.

**이 예시가 보여주는 것**: 재사용 성적을 앞에 두는 배치 · 미작동을 숨기지 않는 판정 · 미분류에 사유 달기 · 과거 거절 이력을 GATE 에 밝히기. 결과는 🟢 3건 전부 발행.

> 0번 섹션의 rule 이름들은 *이 프로젝트*가 앞선 회고에서 발행했던 것들이다. 각자 다를 수밖에 없다 — 베낄 것은 이름이 아니라 판정의 형태다.

---

## 0. 직전 발행물 성적

| rule (발행 시점) | 이번 세션 재사용 | 판정 |
|---|---|---|
| `evidence-before-decision` (3 세션 전) | 인증 정책을 묻기 전에 상류 API 의 인증 3상태를 실측해 대조 · 이번 세션 시작 시 추측 대신 깨진 매니페스트 9종 재고 조사 · 국소·가역 결정 3건은 스스로 정하고 보고 | **강하게 작동.** 이번 세션 첫 행동이 "알려진 문제는 둘뿐이고 나머지는 추측이다 → 측정부터"였는데, 이 rule 이 없었으면 안 했을 행동 |
| `verify-your-evidence` (2 세션 전) | 표적으로 쓰려던 공개 API 를 먼저 확인 → 503 발견해 교체 · 문서에 쓸 주장 3건을 쓰기 전 데모로 확인 · stdout 을 버려 "exit 0"만 보고 넘어갈 뻔한 것을 재측정 | **작동했으나 한 번 밟음** — probe 스크립트가 YAML 문법 오류로 깨진 출력을 "측정 결과"로 한 번 제시했다. rule 이 예고한 세 번째 양상(harness 자체가 틀렸다) 그대로 |
| `adr-rationale-realization` (3 세션 전) | ADR 이 주장한 속성 3개를 실행 출력으로 확인해 보고에 명시 | 작동 |
| memory `milestone-adr-gate-check` | 두 마일스톤 모두 **안에서** ADR 발행, 탈락시킨 것도 사유와 함께 기록 | 2 세션 전의 소급 박제 실패가 반복되지 않음 |

> 배치 주의: 이 표가 **첫 섹션**이다. 뒤로 밀면 안 읽힌다.
> 판정 주의: `verify-your-evidence` 의 "한 번 밟음"을 숨기지 않았다 — 그게 rule 문구를 고칠지 판단하는 유일한 신호다.

## 1. 잘한 것

**엔지니어링**

- **재고 조사가 설계를 바꿨다.** 추측으로 시작했다면 알려진 2건만 잡았을 것. 측정하니 *매니페스트 이름 충돌이 help 를 stdout 에 뱉고 exit 0* 으로 끝난다는, 크래시보다 위험한 것이 나왔다.
- **예약어를 상수로 두지 않고 CLI 자신에게 물었다.** 부수효과로 매니페스트끼리의 이름 충돌이 별도 코드 없이 같은 검사에 걸렸다.
- **순환 의존을 우회할 장애물이 아니라 설계 신호로 읽었다.** 컴파일러가 막은 자리가 곧 모듈 경계였다.

**비즈니스**

- 사용자가 로드맵 밖에서 "검증부터"를 제안했을 때 즉시 수용 — 로드맵보다 백로그 압력이 실제 신호였다.
- 사용자가 "그냥 써 주세요, 코드 보고 이해하겠다"로 전환했을 때 모드를 즉시 바꿨다.

## 2. 실수한 것

**엔지니어링**

- **import 정리 실패 — 세 세션 연속.** 코드를 걷어내며 import 를 안 지워 빌드를 깼다. 컴파일러가 항상 잡으니 비용은 왕복 1회지만 3연속이면 습관 문제.
- **probe 스크립트 자체가 틀렸다.** 증거를 만들고 그 증거를 검증하지 않았다.

**비즈니스**

- **Socratic 강도를 잘못 잡아 "모르겠네요"가 두 번 나왔다.** 막힌 곳은 개념이 아니라 배치였는데 같은 층을 두 번 설명했다.
- **반복 패턴 7개를 균등하게 손코딩 요구했다.** 학습 가치는 앞 2~3개에 몰려 있었다.

## 3. 어려웠던 것

프레임워크의 lazy 초기화 때문에 이름 충돌의 승자가 케이스마다 갈렸고, 측정 없이는 예측이 불가능했다. 별개로 외부 공개 API 가 세션 중에 데이터를 리셋해 실측 표를 처음부터 다시 만들어야 했다.

## 4. 배운 것

1. **가장 위험한 실패는 요란한 것이 아니라 `exit 0` 인 것.**
2. **보조 로직은 실물과 같은 출처·같은 연산을 참조해야 한다.**
3. **컴파일러 에러가 논리 버그를 잡았다** — 미사용 변수 경고를 덮었다면 살아남았을 버그였다.
4. **막힘의 종류를 먼저 식별해야 한다** — 같은 층을 다시 설명하면 두 번째도 실패한다.
5. **실행 흔적이 설명을 이긴다** — 상태 변화 추적표 하나가 두 번의 설명보다 강했다.

**단서** — 과거 미뤄둔 합의에 *"학습 사이클 skill 은 마찰 재현만으로는 트리거가 아니다"* 가 있다. 후보 3 은 그 skill 과 다른 물건(상시 가드레일 vs 절차)이라 후보로 올리되 같은 영역임을 밝힌다. 이번엔 마찰이 **재현**된 게 아니라 **해소 방법이 발견**된 것이 다른 점.
