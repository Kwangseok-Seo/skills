# 회고 산출물 포맷

세션 회고를 **대화에 출력할 때**의 형태. 파일로 저장하는 물건이 아니다 — 세션 대화에 남고, 세션을 봉인하면 스냅샷 본문에 그대로 보존된다.

## 골격

```md
## 0. 직전 발행물 성적

| rule (발행 시점) | 이번 세션 재사용 | 판정 |
|---|---|---|
| `rule-이름` (n 세션 전) | {어디서 어떻게 — 구체 사건} | 작동 / 부분작동 / 미작동 |

## 1. 잘한 것
**엔지니어링** — {사건 앵커된 불릿 2~4개}
**비즈니스** — {2~4개}

## 2. 실수한 것
**엔지니어링** / **비즈니스**

## 3. 어려웠던 것
{한 문단씩 — 잘못이 아니라 비용이 컸던 지점}

## 4. 배운 것
{번호 매긴 항목. 다음 세션이 써먹을 수 있는 형태로}

## 5. 🟢 격상 판정

| # | 노드 | 범주 | 판정 | ROUTE |
|---|---|---|---|---|
| 1 | {한 줄} | b-insights | 🟢 후보 (rule) | `~/.claude/rules/` |
| 4 | {한 줄} | e-recurring | 미분류 | {사유} |

**GATE 는 사람 몫입니다.** {어느 것을 발행할지 묻기 — 반려·수정 가능함을 명시}
```

## 각 섹션 규율

### 0. 재사용 성적

- **첫 섹션이어야 한다.** 이번 세션의 잘잘못보다 먼저. 이유는 SKILL.md 참조.
- rule 이름만 적지 말고 **어디서 어떻게** 를 적는다. "적용됨" 은 판정이 아니다.
- **미작동을 숨기지 않는다.** rule 이 있었는데도 밟았으면 그 사건을 적는다. 반복되면 rule 문구·자리를 고치는 게 새 rule 을 얹는 것보다 낫다.
- 이번 세션과 무관한 rule 은 표에 올리지 않는다. 성적표가 아니라 목록이 된다.
- 아직 발행한 게 없으면 한 줄로 그렇게 적고 넘어간다. 빈 표는 표가 없는 것보다 나쁘다.

### 1~3. 잘한 것 / 실수한 것 / 어려웠던 것

- 모든 불릿이 **이 세션의 관찰 가능한 사건**에 앵커. 수치·출력·에러 문구를 인용할 수 있으면 인용한다.
- **실수 축이 비면 회고가 얕은 것이다.** 에이전트 본인의 실수를 먼저 적는다.
- 어려웠던 것 ≠ 실수. 어려웠던 것은 **비용이 컸던 지점**이고 다음에 도구를 바꿀 후보다.
- 렌즈 구분: 엔지니어링 = 코드·설계·측정. 비즈니스 = 사용자·진도·산출물 형태·협업 마찰(학습 프로젝트면 학습 효율).

### 4. 배운 것

- **다음 세션이 써먹을 수 있는 문장**으로 쓴다. "X 를 배웠다"가 아니라 "X 일 때는 Y 한다".
- 여기 항목이 곧 5단계 🟢 후보의 원료다. 배운 것에 없는 게 후보로 튀어나오면 앞 섹션이 부실한 것.

### 5. 판정표

- 판단은 **이진**: `🟢 후보 (타입)` / `미분류`. 강도 등급 금지.
- **미분류에는 사유를 적는다.** 사유 없는 미분류는 매장이다.
- 범주 열은 코퍼스 5범주 이름을 쓴다 — `a-mistakes` / `b-insights` / `c-improvements` / `d-deferred` / `e-recurring`. 정의는 SKILL.md 6단계에 있다. 코퍼스를 안 써도 이름은 유지한다 — *어떤 종류*의 것인지 말하게 강제하는 장치다.
- 표 아래에 **단서**를 단다: 과거 거절 이력, 인접 rule 과의 경계, 발행 시 주의할 문구 등.

## 분량

전체가 한 화면에 안 들어와도 되지만, **표가 목록으로 변질되면 실패**다. 각 섹션 2~4항목이 건강한 범위다. 항목이 계속 늘면 세션을 더 잘게 나눴어야 한다는 신호.

## 안티패턴

- ❌ "테스트 통과함, 잘 진행됨" 류의 검증 불가능한 문구
- ❌ 실수 축에 "특별히 없음"
- ❌ 재사용 성적을 마지막에 배치 (그러면 안 읽힌다)
- ❌ 🟢 후보를 선택지 버튼으로 제시 (읽기가 강제되지 않아 거수기가 된다)
- ❌ 코드 diff 나열 — 회고는 무엇을 했는지가 아니라 **무엇을 알게 됐는지**다
