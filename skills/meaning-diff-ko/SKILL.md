# 줄 의미 diff — 바뀐 줄만이 아니라 모든 줄의 뜻을 리뷰한다

리뷰어는 메서드 안에서 한 줄씩 읽는데, diff 는 글자가 바뀐 줄만 보여 준다. 위에 새 가드가 생겨 **언제 실행되는지**가 바뀌었는데 글자는 그대로인 줄은 보이지 않는다 — 그리고 버그는 흔히 거기 있다.

이 스킬은 바뀐 함수를 행 표로 다시 짓는다. 줄마다 전/후 문장을 하나씩 적고, 행마다 태그를 붙이고, 그 태그를 두 버전에 돌린 테스트로 증명한다. 공통 형식 — 행, 태그, 증거 규칙 — 은 [FORMAT.md](FORMAT.md) 에 있다. 2단계 전에 읽는다.

## 인자

| 인자 | 모드 | 대상 |
|---|---|---|
| `[review] <대상>` | review (기본) | 커밋(`61d683d`), 범위(`main..feature`), 브랜치, PR 번호(`#123`, `gh` 필요) |
| `pr [<base>]` | pr | 현재 브랜치를 `<base>` 와 비교 (기본: repo 기본 브랜치) |
| `pr <base>..<브랜치>` | pr | 체크아웃하지 않은 브랜치 |
| (없음) | review | `HEAD` |

대상 뒤의 자유 텍스트는 범위를 좁힌다: `review #123 is_close_all 만`.

## 절차

### 0. base 와 head 확정

- 커밋 `X` → base `X^`, head `X`
- 범위 `A..B` → base `merge-base A B`, head `B`
- PR `#N` → `gh pr view N --json baseRefOid,headRefOid`, 없으면 `git fetch origin <둘 다>`
- `pr` 모드 → base `merge-base <base> HEAD`, head `HEAD` (브랜치를 주면 그 브랜치). 작업 트리에 커밋 안 된 변경이 있으면 그렇다고 말하고 커밋만 분석

확정된 `base..head` 와 바뀐 파일 목록을 먼저 출력한다.

### 1. 함수 범위 (기계적)

```bash
git diff -W <base> <head> -- <파일>        # 들여쓰기가 문법이 아닌 언어에서만 -w 추가
```

`-W` 는 각 hunk 를 감싸는 함수 전체로 넓힌다 — git 이 보는 함수다. diff driver 가 없으면 git 은 들여쓰기 없는 줄을 함수 머리로 보므로, Python 에선 메서드 hunk 가 클래스 전체로 커진다. repo 의 `.gitattributes` 가 그 언어의 driver 를 정하지 않으면 이 명령에만 넘긴다: 임시 파일에 `*.py diff=python` 을 쓰고(git 은 `java`, `cpp`, `csharp`, `golang`, `rust`, `ruby`, `php`, `kotlin` … 도 내장) `git -c core.attributesFile=<그 파일> diff -W …` 로 돌린다. `-w` 는 공백만 바뀐 변경을 지워 C 계열 언어에선 잡음을 줄이지만, 들여쓰기가 문법인 언어(Python, YAML, Haskell, Makefile)에선 **실제 변경을 숨긴다**: `elif` 에서 중첩 `if` 안으로 옮겨진 줄이 안 바뀐 것으로 나온다. 나타난 함수를 `A`, `B`, … 로 이름 붙여 나열한다 — 이 문자가 행 id 의 접두어다. 바뀐 함수의 **안 바뀐 호출부**도 호출부 동작이 달라질 수 있으면 넣는다; ★ 가 가장 자주 숨는 곳이다. 코드가 아닌 파일(lock, 생성 파일, 문서)은 건너뛰고 무엇을 건너뛰었는지 말한다.

바뀐 함수가 **5개**를 넘으면 전부 한 줄 요약과 함께 나열하고, 제어 흐름이나 반환값이 바뀐 것을 다룬다. 건너뛴 것은 이름과 이유를 적는다. 사용자가 나중에 어느 것이든 요청할 수 있다.

### 2. 줄 의미 diff

범위 안의 함수마다 hunk 만이 아니라 전/후 **전체** 버전(`git show <base>:<경로>`, `git show <head>:<경로>`)을 읽고 FORMAT.md 대로 행을 만든다. 함수의 모든 줄이 어떤 행에든 들어간다; 묶을 수 있는 것은 평범한 `동일` 줄의 연속뿐이다. 핵심 작업은 ★ 찾기다: 안 바뀐 줄마다 이제 다른 조건에서 실행되는지, 다른 입력을 보는지 묻는다.

### 3. 경로 그림

제어 흐름이 바뀐 함수마다 Mermaid `flowchart TD` 를 전 하나, 후 하나. 노드는 분기와 반환이고 행 id 를 라벨에 단다. 템플릿의 `classDef` 로 칠한다: `new`/`changed` 초록, `star` 노랑, `warn` 은 외부 맥락 — 점선 노드에서 그것이 먹이는 분기로 점선 간선(`X -.-> C`).

### 4. diff 밖의 맥락

범위 안의 함수마다:

- **호출부** — repo 에서 이름을 검색해, 각 호출부가 `신규`/`변경`/`★` 행이 읽는 인자를 어떻게 만드는지 보인다.
- **생산자** — 그런 인자마다 그 값을 만드는 함수를 연다. **성공도 돌려줄 수 있는 값을 돌려주는 실패 경로**(`[]`, `None`, `0`, `-1`, `""`)를 가장 세게 본다: 호출부는 "없음"과 "조회 실패"를 구별하지 못하고, 그 값 위에 지은 가드는 조용히 꺼진다. 그런 행에 ⚠ 를 단다.

발췌는 중요한 줄만 남기고 결정적인 토큰을 강조한다.

### 5. 테스트 — 전, 후, 변이

각각 행을 가리키는 테스트를 쓰고(FORMAT.md, 증거) `T1`, `T2`, … 로 번호를 붙인다. ★ 마다 **두 버전이 공유하는 코드**(보통 호출부)로 들어가는 테스트를 하나 넣어, 전 코드의 실패가 없는 매개변수가 아니라 단언 실패가 되게 한다. 그다음 사용자의 작업 트리는 건드리지 않고 **같은** 테스트 파일을 버전마다 돌린다:

```bash
git worktree add --detach <tmp>/before   <base>
git worktree add --detach <tmp>/after    <head>
git worktree add --detach <tmp>/mutant-1 <head>   # 약한 행의 토큰 하나를 바꾼다; 변이는 최대 3개
```

- 테스트 파일은 worktree **밖**에 두고 러너를 각 worktree 로 향하게 한다. 프로젝트 자신의 테스트 헬퍼를 import 하면(`from tests.helpers import …`) 실행할 때만 각 worktree 의 테스트 패키지에 복사하고 바로 지워 worktree 를 다시 깨끗하게 둔다. Python: `cd <worktree> && PYTHONPATH=<worktree> PYTHONDONTWRITEBYTECODE=1 python -m pytest -p no:cacheprovider <테스트파일 절대경로>` (PowerShell: `$env:PYTHONPATH`, `$env:PYTHONDONTWRITEBYTECODE` 를 먼저 설정). 캐시 스위치 둘이 worktree 에 추적 안 되는 파일을 남기지 않아 강제 없이 지울 수 있다. 프로젝트 자신의 러너와 의존성을 쓴다.
- 의존성이 설치돼 있지 않으면 FORMAT.md 대로 stub 하고(시험하는 행이 쓰는 심볼은 역할 유지) stub 목록을 페이지에 적는다. 생성자가 무거운 클래스의 메서드를 부를 땐 `Cls.__new__(Cls)` 로 객체를 만들고 그 메서드가 읽는 속성만 넣는다. **후 코드를 먼저 돌린다: 전부 통과해야** 전·변이 열이 의미를 가진다.
- **돌리기 전에 변이를 확인한다:** `git -C <mutant> diff --stat` 이 바꾸려던 한 줄만 보여야 한다. 두 곳에 걸렸거나 안 걸린 변이는 후 코드의 사본이 되고, 그러면 모든 테스트가 *못 잡음* 으로 읽힌다 — 약한 결과가 아니라 거짓 결과다.
- 테스트·열마다 통과/실패를, 실패마다 한 줄 이유(`TypeError`, 단언)를 기록한다.
- 정리는 `--force` 없이: 변이를 되돌리고(`git -C <경로> checkout -- .`), 모든 worktree 를 `git worktree remove <경로>` 로 지운 뒤 `git worktree prune` 과 `git worktree list` 로 확인한다. 제거가 거부되면 강제하지 말고 `git -C <경로> status` 를 사용자에게 보인다. worktree 를 밖의 무엇에도 링크(심링크, junction)하지 않는다 — 강제 제거는 링크를 따라가 대상을 지운다.

함수를 격리해 돌릴 수 없으면 그 함수는 이 단계를 건너뛰고, 칸을 비우고, 추정 태그에 `(추정)` 을 유지한다.

### 6. 질문

⚠ 행마다 질문 하나: 질문 한 줄, 그 아래 지금 무슨 일이 일어나는지(고정 테스트로 본 것)와 왜 틀렸을 수 있는지.

## 출력 — review 모드

[templates/review.html](templates/review.html) 로 만든 단일 HTML 파일: 머리말, 범례, 여섯 절을 순서대로, 테스트 코드는 `<details>` 안에. `<repo>/.claude/meaning-diff/<짧은 sha>-review.html` (PR 이면 `pr-<N>-review.html`)에 쓴다. 그 repo 에서 `.claude/` 가 git 무시 대상이 아니면 추적 안 되는 파일로 나타난다고 말한다.

호스트가 HTML 페이지를 게시하는 도구(예: Claude 의 Artifact 도구)를 제공하면 거기 게시도 제안한다; 아니면 파일 경로를 준다. 자동으로 열지 않는다.

끝에 짧은 터미널 요약: ★ 행과 증거 강도, ⚠ 질문, 열별 테스트 합계(`전 6F/4P · 후 10P · mutant-1 2F/8P`).

## 출력 — pr 모드

[templates/pr-body.md](templates/pr-body.md) 로 만든 Markdown 파일 하나를 `<repo>/.claude/meaning-diff/<브랜치>-pr.md` (브랜치 이름의 `/` 는 `-` 로)에 쓰고 출력한다. 읽는 사람은 PR 페이지를 훑는 리뷰어이므로:

- 요약 표에는 `동일` 이 **아닌** 행만 넣는다. 전체 행 표는 `<details>` 안에.
- 6절은 **묻기 전에 답함**(⚠ 질문과 작성자의 답 — 답마다 사용자에게 묻는다; 사용자가 거절할 때만 `TODO(작성자)` 를 남긴다)과 **알려진 한계**가 된다.
- GitHub 는 ```` ```mermaid ```` 블록, 표, `<details>` 를 렌더링한다; HTML 페이지의 나머지는 넘어가지 않는다. PR 본문 한도는 65,536자 — 넘으면 전체 행 표와 테스트 코드를 빼고 그렇다고 말한다.

그다음 각각 따로, 명시적 승인을 받았을 때만 제안한다:

1. **게시** — 기존 PR 이면 `gh pr edit <N> --body-file <파일>`, 없으면 `gh pr create --body-file <파일>`. 글을 공개하는 일이니 승인 없이 실행하지 않는다.
2. **테스트 커밋** — repo 의 테스트 디렉터리로 옮기고, 이름을 행 id 대신 동작 이름으로 바꾼다.

## 규칙

- **전 열은 실제로 돌렸을 때만 증거다.** 전/후/변이 칸을 추론으로 채우지 않는다.
- **분석 대상 repo 를 수정하지 않는다** — 출력 파일과 pr 모드 제안에서 사용자가 승인한 것 말고는. 다른 커밋, stash, 사용자 작업 트리에서의 checkout 은 없다. worktree 는 임시 디렉터리 아래에 둔다.
- **질문은 작성자에게 묻는 것이지 판정이 아니다.** ⚠ 테스트는 무슨 일이 일어나는지 고정할 뿐, 그 동작이 틀렸다고 말하지 않는다.
- **깊이를 변경 크기에 맞춘다.** 이름만 바꾼 변경은 그렇다고 말하는 짧은 페이지: 모든 행 `글자만 변경`, 양쪽 테스트, ★ 없음.
