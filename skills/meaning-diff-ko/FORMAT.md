# 줄 의미 diff 형식 — 두 모드 공통

`review` 와 `pr` 모드는 같은 분석을 짓고 보여 주는 방식만 다르다. 독자가 한 행을 믿는 데 필요한 것은 전부 여기 있다: 행, 태그, 그 태그의 증거.

## 행

행은 한 줄이거나, 한 문장으로 읽히는 인접한 몇 줄이다(여러 줄로 나뉜 시그니처, 대칭 값을 반환하는 `if`/`else` 한 쌍). 행은 **후** 버전의 줄 순서를 따른다; 지워진 줄은 원래 있던 자리에 둔다. 함수의 모든 줄이 어떤 행에든 들어간다 — 안 바뀐 줄도. 뜻 변경이 숨는 곳이 바로 안 바뀐 줄이다.

- **묶기.** `동일` 이 아닌 줄과 ★ 후보는 모두 자기 행을 갖는다. ★ 후보가 없는 `동일` 줄의 연속은 한 행으로 묶을 수 있다(`A9 동일, 17줄 — 주문 요청을 만든다`).
- **단순 읽기는 소비자를 따른다.** 값을 읽거나 대입만 하는 줄(`point = float(p['point'])`)은 자기 태그를 갖지 않고 그 값을 쓰는 행의 태그를 따른다. 값 자체가 바뀐 경우는 예외.

각 행이 담는 것:

| 필드 | 내용 |
|---|---|
| id | 범위 안 함수는 1절이 나열한 순서대로 `A`, `B`, …; 소스 줄이 아니라 **행**에 번호를 함수마다 후 버전 순서로 매기고, 여러 줄에 걸친 행도 id 는 하나다(`A3`, `A12`). 지워진 행은 바로 뒤에 오던 행의 id 에 `−` 를 붙인다(`A7−`) |
| 전 코드 / 후 코드 | 정확한 텍스트, 그쪽에 없으면 *(없음)* |
| 전 문장 / 후 문장 | 그 줄이 **이 함수의 이 지점에서** 하는 일 — 문법의 의역이 아니다. 언제 도달하는지, 입력이 어디서 오는지가 바뀌었으면 그것도 적는다 |
| 태그 | 아래 여섯 중 하나, 해당하면 ⚠ 추가 |
| 맥락 | 선택: 그 행의 뜻이 기대는 함수 밖의 사실 (4절) |
| 테스트 | 테스트 행렬의 테스트 id (`T1`, `T4`), 또는 테스트를 돌릴 수 없었던 이유 한 줄 |

## 태그 — 글자 × 뜻

행마다 두 질문: *글자가 바뀌었나?* 와 *뜻이 바뀌었나?* 뜻에는 무엇을 계산하는지뿐 아니라 **언제 도달하는지**와 **입력이 무엇일 수 있는지**가 들어간다.

| | 뜻 동일 | 뜻 변경 |
|---|---|---|
| **후에만 있음** | — | `신규` |
| **전에만 있음** | — | `삭제` |
| **글자 동일** | `동일` | `★ 글자 동일·뜻 변경` |
| **글자 변경** | `글자만 변경` | `변경` |

- **들여쓰기가 문법인 곳(Python, YAML, Haskell, Makefile)에선 들여쓰기도 글자다.** 블록 안팎으로 옮겨지기만 한 줄도 글자가 바뀐 것이다 — `변경` 이거나 ★ 이지, 결코 `동일` 이 아니다.
- `★` 가 이 형식이 있는 이유다. 글자가 안 바뀐 줄은 일반 diff 에 나오지 않지만, 위의 새 가드, 새 호출부, 입력 생산자의 변경이 그 줄이 언제 실행되고 무엇을 보는지를 바꿀 수 있다. **어떤 입력이 이제 그 줄을 통해 다른 관찰 가능한 효과를 내면** ★ 다 — 다른 반환값, 일어나거나 건너뛰어진 호출, 다르게 넘겨지는 값. 새·바뀐 분기 뒤에 있는 안 바뀐 줄, 생산자가 바뀐 값을 읽는 줄, 그리고 **바뀐 함수의 안 바뀐 호출 지점**마다 찾는다.
- `⚠ 물을 것` 은 일곱째 칸이 아니다. diff 가 결론 내지 않는 무언가에 옳고 그름이 달린 행에 덧붙인다 — 정상 값과 겹치는 삼켜진 에러, 이유가 적히지 않은 매직 넘버, 호출부 쿼리가 정하는 순서, 따로 조회해 일치한다고 가정한 두 값. ⚠ 행은 반드시 6절 질문 하나를 낳는다.

## 증거 — 태그를 사실로 적기 전에 필요한 것

분석이 *추정한* 태그와 테스트가 *보인* 태그는 표시하지 않으면 페이지에서 똑같아 보인다. 5절 테스트를 돌리고 적용한다:

- **강함** — 전 실패가 단언 실패이고, 두 버전이 공유하는 진입점으로 도달했다
- **약함** — 전 실패가 기능 부재만 보인다(아래 참고); 변이가 잡았는지 함께 적는다
- **추정** — 돌린 테스트가 없다; 태그에 `(추정)` 이 붙는다

터미널 요약과 페이지는 `신규`/`변경`/`★` 행마다 이 셋 중 하나를 밝힌다.

| 태그 | 확정하는 증거 |
|---|---|
| `신규`, `변경`, `★` | **전에서 실패하고 후에서 통과**하는 테스트 |
| `삭제` | **전에서 통과하고 후에서 실패**하는 테스트, 또는 그 동작이 이제 도달 불가능하다는 설명과 이유 |
| `동일`, `글자만 변경` | **양쪽에서 통과**하는 테스트 |
| 실행되지 않는 줄(주석, docstring, 런타임에 검사하지 않는 annotation)의 모든 태그 | 없음 — 테스트 칸에 *동작 없음* |
| `⚠` | **현재 후 동작을 고정**하는 테스트 — 무슨 일이 일어나는지 보일 뿐 옳은지는 아니다. 그건 작성자가 답한다 |

- **두 버전이 공유하는 것으로 시험한다.** 새 매개변수를 부르는 테스트는 전에서 `TypeError` / `AttributeError` / `ImportError` 로 실패한다 — API 가 새것임을 증명할 뿐 동작이 옳음을 증명하지 않는다. 강한 증거는 진입점이 **두 버전에 똑같이 있고**(보통 호출부) 전 실패가 단언 실패인 테스트에서 나온다. ★ 마다 그런 테스트를 우선한다.
- **약한 행엔 변이.** 전 실패가 기능 부재뿐인 `신규`/`변경`/`★` 행마다 변이 하나를 만든다: 후 사본에서 그 행의 토큰 하나(인덱스, 연산자, 상수)를 바꾸고 모든 테스트를 돌려 어느 것이 잡는지 보고한다. 변이는 최대 3개; 그 밖의 약한 행은 *미검증* 으로 남긴다. 그 행의 변이에서 여전히 통과하는 테스트는 그 행을 뒷받침하지 않는다.
- **mock 된 경계.** 테스트가 생산자를 바로 던지거나 돌려주는 mock 으로 바꾸면 그쪽으로 넘어가는 인자를 보지 못한다; 그 인자의 변이는 호출 단언만 잡는다. 알려진 한계에 적고, 동작 테스트를 그 인자의 증거로 세지 않는다.
- **후가 먼저 전부 통과해야 한다.** 후에서 실패하는 테스트가 있으면 harness(잘못된 stub, 잘못된 경로)나 테스트가 틀린 것이다 — 전·변이 열을 읽기 전에 그것부터 고친다. 깨진 후 옆의 전 실패는 증거가 아니다.
- **실행 없으면 ★ 없음.** 테스트 결과가 없으면 `★ (추정)` / `변경 (추정)` 으로 적는다. 추정 태그를 확정처럼 적지 않는다.
- **돌릴 수 없음.** 함수가 DB, 브로커, 현재 시각, 네트워크를 필요로 하고 단순 stub 으로 격리되지 않으면 테스트 칸을 비우고 이유를 한 줄 적는다. *미설치 모듈*의 stub 은 괜찮다 — stub 한 모듈을 페이지에 나열한다 — 단, 시험하는 행이 쓰는 심볼은 stub 에서도 역할을 유지해야 한다(예외 클래스는 던지고 잡을 수 있게, 상수는 값 그대로). 문제의 그 줄을 stub 으로 치워 버린 테스트는 그 줄의 증거가 아니다.
- **테스트는 리뷰 증거이지 기여물이 아니다.** review 모드에선 repo 밖에 두고, pr 모드에선 작성자 동의가 있을 때만 넣는다. 리뷰 중엔 행 이름으로 짓고(`test_A5_buy_holds_between_threshold_and_anchor`), 커밋한다면 동작 이름으로 바꾼다.

## 여섯 절

| # | 절 | 만드는 것 |
|---|---|---|
| 1 | 함수 범위 | `git diff -W` — 기계적, 모델이 아님 |
| 2 | 줄 의미 diff | 위의 행, 함수마다 한 블록 |
| 3 | 경로 그림 | Mermaid `flowchart` 전·후; `신규`/`변경`/`★` 노드만 칠함; 분기를 먹이는 외부 맥락은 점선 노드 |
| 4 | diff 밖의 맥락 | 함수의 호출부, `신규`/`변경`/`★` 행이 읽는 값의 생산자 |
| 5 | 테스트 행렬 | 테스트마다 한 행: id, 이름, 행 id, 입력 → 기대, 전, 후, 변이마다 한 열 |
| 6 | 질문 | review: *작성자에게 물을 것*. pr: *묻기 전에 답함*, *알려진 한계* |
